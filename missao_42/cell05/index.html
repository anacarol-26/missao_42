Antes de decorar comandos: entenda o mapa

Git trabalha com três lugares principais e um remoto:

🖥️ Working tree

Os arquivos que você está editando agora.

📦 Staging area

O “rascunho do próximo commit”. O git add coloca mudanças aqui.

🧠 Repository

O histórico de commits guardado pelo Git na pasta .git.

☁️ Remote

Uma cópia/referência hospedada fora do computador, como no GitHub.

editar → git add → staging → git commit → histórico local → git push → GitHub

GitHub → git fetch/pull → repositório local
Decore esta frase: add prepara · commit registra · push envia · fetch busca sem integrar · pull busca e integra.

1 · Configuração inicial

Normalmente feita uma vez por computador/ambiente.

Nome do autor

git config --global user.name "Seu Nome"

Nome associado aos seus commits.

E-mail do autor

git config --global user.email "voce@email.com"

E-mail associado aos commits.

Listar configuração

git config --list --show-origin

Mostra valores e de onde vieram.

Ver um valor

git config user.name

Troque por user.email, por exemplo.

Editor

git config --global core.editor "code --wait"

Define VS Code como editor, se o comando code estiver disponível.

Branch padrão

git config --global init.defaultBranch main

Faz novos git init começarem em main.

Configuração local

git config user.email "outro@email.com"

Sem --global, vale apenas para o repositório atual.

Remover configuração

git config --global --unset user.name

Remove uma configuração global específica.

2 · Criar, clonar e inspecionar repositórios

Inicializar

git init

Cria um repositório Git na pasta atual.

Clonar

git clone https://github.com/usuario/projeto.git

Baixa arquivos, histórico e configuração do remoto.

Clonar em pasta específica

git clone URL nome-da-pasta

Escolhe o nome da pasta local.

Clonar apenas parte do histórico

git clone --depth 1 URL

Cria um clone raso, útil quando o histórico completo não é necessário.

Ver versão

git --version

Confirma a instalação do Git.

Ajuda geral

git help

Abre a documentação de ajuda do Git.

Ajuda de um comando

git help commit

Documentação completa do comando.

Ajuda rápida

git commit -h

Opções resumidas do comando.

3 · Status, add e staging

Status

git status

Mostra branch atual, arquivos modificados, staged e não rastreados.

Status curto

git status --short

Versão compacta do status.

Add um arquivo

git add arquivo.html

Coloca o arquivo no staging.

Add vários

git add index.html style.css script.js

Prepara arquivos específicos.

Add tudo

git add .

Prepara alterações da pasta atual e subpastas.

Add interativo

git add -p

Permite escolher trechos específicos das mudanças.

Tirar do staging

git restore --staged arquivo.html

Remove do próximo commit, mantendo a alteração no arquivo.

Ver staging

git diff --staged

Mostra exatamente o que está preparado.

4 · Commits

Criar commit

git commit -m "Adiciona login"

Registra o staging no histórico.

Commit + add de rastreados

git commit -am "Corrige formulário"

Inclui alterações de arquivos já rastreados; não inclui arquivos novos.

Alterar último commit

git commit --amend -m "Nova mensagem"

Substitui o commit mais recente.

Amend mantendo mensagem

git commit --amend --no-edit

Adiciona o staging ao último commit sem mudar sua mensagem.

Commit vazio

git commit --allow-empty -m "Inicia deploy"

Cria um commit mesmo sem alteração de arquivo.

Ver commits recentes

git log --oneline -10

Mostra os 10 últimos em formato resumido.

Boa mensagem: prefira algo como Adiciona validação do formulário em vez de mudanças ou teste.

5 · Branches

Listar locais

git branch

A branch atual aparece com *.

Listar todas

git branch -a

Inclui referências remotas conhecidas.

Criar

git branch feature/login

Cria sem trocar de branch.

Criar e trocar

git switch -c feature/login

Forma moderna e explícita.

Trocar

git switch main

Muda para uma branch existente.

Forma clássica

git checkout -b feature/login

Cria e troca. Ainda é muito encontrado em tutoriais.

Renomear atual

git branch -M main

Renomeia a branch atual forçando se necessário.

Excluir local

git branch -d feature/login

Exclusão segura de branch já integrada.

Excluir forçado

git branch -D feature/login

Pode apagar trabalho não integrado.

Renomear

git branch -m antigo novo

Renomeia uma branch local.

6 · Merge e conflitos

Integrar branch

git switch main git merge feature/login

Integra a branch na branch atual.

Abortar merge

git merge --abort

Tenta voltar ao estado anterior ao merge em andamento.

Merge sem fast-forward

git merge --no-ff feature/login

Força um commit de merge, preservando visualmente a integração da branch.

Ver conflito

git status

O Git informa quais arquivos precisam ser resolvidos.

Fluxo de conflito:
1. abra o arquivo · 2. procure <<<<<<<, =======, >>>>>>> · 3. escolha/edite o conteúdo correto · 4. git add arquivo · 5. finalize o merge com git commit ou o comando indicado pelo Git.

7 · Rebase

Rebase reescreve a sequência de commits para reaplicá-los sobre outra base. É poderoso, mas exige cuidado com histórico já compartilhado.

Rebase simples

git switch feature/login git rebase main

Reaplica os commits da feature sobre a ponta de main.

Continuar após conflito

git add arquivo git rebase --continue

Depois de resolver o conflito.

Abortar

git rebase --abort

Interrompe e tenta retornar ao estado anterior.

Rebase interativo

git rebase -i HEAD~5

Permite reordenar, editar, juntar (squash) ou remover commits locais.

Cuidado: rebase muda os identificadores dos commits. Evite reescrever commits que outras pessoas já usam como base sem coordenação.

8 · Remotos: GitHub, origin e upstream

Listar remotos

git remote -v

Mostra URLs de fetch e push.

Adicionar remoto

git remote add origin URL

O nome origin é convencional.

Detalhar remoto

git remote show origin

Mostra informações sobre branches e rastreamento.

Alterar URL

git remote set-url origin NOVA_URL

Troca o endereço do remoto.

Remover remoto

git remote remove origin

Remove a configuração local do remoto.

Renomear remoto

git remote rename origin upstream

Troca o nome do remoto.

origin ≠ GitHub. origin é só um apelido local para uma URL. Você poderia chamar de github, empresa, upstream etc.

9 · Fetch, pull e push

Buscar sem integrar

git fetch origin

Atualiza referências remotas sem alterar sua branch de trabalho.

Buscar tudo

git fetch --all

Busca dos remotos configurados.

Pull da main

git pull origin main

Busca e integra a main remota na branch atual.

Pull com rebase

git pull --rebase origin main

Busca e tenta reaplicar seus commits locais sobre o remoto.

Primeiro push

git push -u origin main

Publica e configura upstream.

Push normal

git push

Envia a branch rastreada.

Publicar branch

git push -u origin feature/login

Cria a referência remota da branch.

Apagar branch remota

git push origin --delete feature/login

Remove a branch do remoto.

Evite git push --force sem entender o impacto. Ele pode sobrescrever histórico remoto. Quando reescrita for realmente necessária, --force-with-lease oferece uma proteção adicional contra sobrescrever trabalho remoto inesperado.

10 · Tags, versões e releases

Listar tags

git tag

Lista tags locais.

Criar tag simples

git tag v1.0.0

Marca o commit atual.

Tag anotada

git tag -a v1.0.0 -m "Primeira versão"

Cria uma tag anotada com metadados.

Tag em commit específico

git tag -a v1.0.0 a1b2c3d -m "Release"

Marca outro commit.

Enviar uma tag

git push origin v1.0.0

Publica uma tag.

Enviar todas

git push origin --tags

Envia tags locais ainda não publicadas.

Excluir tag local

git tag -d v1.0.0

Remove a tag local.

Excluir tag remota

git push origin --delete v1.0.0

Remove a tag do remoto.

No GitHub, uma Release pode ser associada a uma tag e incluir notas/artefatos. Release é um recurso do GitHub; tag é um recurso do Git.

11 · Stash: guardar trabalho temporariamente

Guardar

git stash

Guarda alterações rastreadas e deixa a working tree limpa.

Guardar com nome

git stash push -m "login em andamento"

Ajuda a identificar o stash.

Incluir não rastreados

git stash -u

Inclui arquivos novos não rastreados.

Listar

git stash list

Mostra os stashes existentes.

Aplicar e manter

git stash apply stash@{0}

Aplica sem remover da lista.

Aplicar e remover

git stash pop

Aplica o mais recente e normalmente o remove.

Apagar stash

git stash drop stash@{0}

Remove um stash específico.

Limpar todos

git stash clear

Remove todos os stashes. Use com cuidado.

12 · Desfazer alterações sem entrar em pânico

Descartar alteração de arquivo

git restore arquivo.js

Restaura o arquivo para o estado do índice/HEAD conforme o contexto.

Desfazer todos os arquivos locais

git restore .

Descarta alterações não staged da pasta. Cuidado: pode perder trabalho.

Tirar do staging

git restore --staged .

Retira tudo do staging sem apagar o conteúdo alterado.

Reverter commit público

git revert a1b2c3d

Cria um novo commit inverso. Geralmente adequado para histórico já compartilhado.

Voltar um commit mantendo staged

git reset --soft HEAD~1

Remove o commit da ponta, mantendo mudanças no staging.

Voltar mantendo arquivos fora do staging

git reset HEAD~1

O modo padrão é mixed.

Voltar e descartar

git reset --hard HEAD~1

Move HEAD e descarta mudanças no caminho. Extremamente destrutivo.

Remover arquivos não rastreados

git clean -n

Primeiro simule com -n. Só depois considere git clean -f.

13 · Recuperação: reflog

O reflog registra movimentos de referências locais, sendo uma das melhores ferramentas quando você acha que “perdeu” um commit.

Ver reflog

git reflog

Mostra movimentos recentes de HEAD e referências locais.

Inspecionar posição

git show HEAD@{2}

Inspeciona uma posição anterior registrada.

Criar branch de recuperação

git branch recuperacao a1b2c3d

Cria uma referência para um commit encontrado no reflog.

Regra prática: se você fez um reset/rebase errado e o commit sumiu do histórico visível, não entre em pânico. Consulte git reflog antes de tentar outras operações.

14 · Log, show, diff e inspeção

Histórico completo

git log

Mostra histórico detalhado.

Uma linha por commit

git log --oneline

Formato compacto.

Gráfico

git log --oneline --graph --decorate --all

Excelente para entender branches.

Arquivo específico

git log -- arquivo.js

Histórico daquele caminho.

Alterações não staged

git diff

Compara working tree com staging.

Alterações staged

git diff --cached

Compara staging com HEAD.

Dois commits

git diff main..feature/login

Compara estados entre referências.

Detalhar commit

git show a1b2c3d

Mostra metadados e patch do commit.

Quem mudou cada linha

git blame arquivo.js

Identifica o commit associado a cada linha.

Resumo de arquivos

git diff --stat

Resumo do tamanho das alterações.

15 · Encontrar coisas no histórico

Buscar mensagem

git log --grep="login"

Procura texto nas mensagens dos commits.

Buscar conteúdo

git log -S"nomeDaFuncao" -- arquivo.js

Encontra commits que adicionaram/removeram uma ocorrência.

Buscar regex no conteúdo

git log -G"padrao.*regex" -- arquivo.js

Procura mudanças que afetam linhas correspondentes ao padrão.

Localizar commit por autor

git log --author="Ana"

Filtra pelo autor.

Localizar arquivo

git log --follow -- arquivo.js

Tenta acompanhar o histórico através de renomeações.

Encontrar introdução de bug

git bisect start git bisect bad git bisect good a1b2c3d

Usa busca binária no histórico. Teste cada commit e marque git bisect good ou git bisect bad; finalize com git bisect reset.

16 · .gitignore e arquivos não rastreados

Crie um arquivo chamado .gitignore na raiz. Ele define padrões que o Git deve ignorar.

# dependências node_modules/ # ambiente .env .env.* # build dist/ build/ # sistema .DS_Store Thumbs.db # IDE .vscode/

Ver ignorados

git status --ignored

Ajuda a conferir se uma regra está funcionando.

Descobrir regra

git check-ignore -v arquivo.log

Mostra qual regra está ignorando o arquivo.

Parar de rastrear mantendo arquivo

git rm --cached .env

Depois coloque .env no .gitignore e faça commit.

Importante: .gitignore não remove um segredo que já entrou no histórico. Se uma chave/API token foi publicada, trate-a como comprometida, revogue/rotacione a credencial e depois cuide da limpeza do histórico.

17 · Conflitos: como resolver

Quando o Git não consegue escolher automaticamente entre duas alterações, você verá marcadores semelhantes a:

<<<<<<< HEAD seu conteúdo ======= conteúdo da outra branch >>>>>>> feature/login

1. Identifique

git status

Veja os arquivos em conflito.

2. Edite

Abra cada arquivo e escolha/combina o conteúdo correto. Remova os marcadores.

3. Marque resolvido

git add arquivo-em-conflito

Indica ao Git que o arquivo foi resolvido.

4. Continue

git commit

No merge. No rebase, normalmente use git rebase --continue.

18 · GitHub: o que existe além do Git

Git é a ferramenta de versionamento. GitHub é uma plataforma que acrescenta colaboração, hospedagem e automações.

Repository

Projeto hospedado no GitHub, com código, histórico, configurações e colaboração.

Pull Request

Proposta de integrar mudanças de uma branch em outra, com revisão e discussão.

Issue

Registro de bug, tarefa, ideia ou discussão relacionada ao projeto.

Actions

Automação/CI/CD definida por workflows, normalmente em .github/workflows/*.yml.

Releases

Publicação de versões do projeto normalmente associadas a tags.

Fork

Cópia de um repositório na sua conta/organização, comum em colaboração com projetos de terceiros.

SSH

Forma de autenticação para Git remoto usando chaves SSH. Alternativamente, HTTPS pode ser usado.

README

Documento de apresentação do projeto. Normalmente README.md.

Fluxo clássico no GitHub

clone → branch → editar → add → commit → push → Pull Request → revisão → merge → atualizar local

19 · Segurança e autenticação

Não commite segredos

Senhas, tokens, chaves privadas, credenciais de banco e arquivos de ambiente com segredos não devem ser enviados ao repositório.

SSH

ssh-keygen -t ed25519 -C "voce@email.com"

Gera uma chave SSH em ambientes que suportam esse método.

Testar conexão SSH

ssh -T git@github.com

Testa autenticação SSH com o GitHub depois de configurar a chave.

HTTPS

Ao usar HTTPS com GitHub, a autenticação deve seguir os mecanismos atuais do GitHub; senhas de conta não são usadas como substituto de autenticação moderna.

Se um segredo vazou: revogue/rotacione a credencial primeiro. Apagar o arquivo no commit mais recente não garante que ele desapareceu do histórico, clones, caches ou logs.

20 · Submodules

Submodule permite registrar outro repositório Git como dependência dentro de um projeto.

Adicionar

git submodule add URL caminho

Registra o repositório externo no projeto.

Inicializar após clone

git submodule update --init --recursive

Baixa submodules, inclusive aninhados.

Atualizar

git submodule update --remote --merge

Atualiza conforme a configuração do submodule.

Ver status

git submodule status

Mostra o commit registrado de cada submodule.

21 · Hooks

Hooks são scripts executados em determinados eventos do Git, como antes de um commit ou depois de receber alterações.

Onde ficam

.git/hooks/

Um repositório possui exemplos de hooks nesse diretório.

Ver caminho dos hooks

git rev-parse --git-path hooks

Mostra o diretório efetivo usado pelo repositório.

Desabilitar hook temporariamente

git commit --no-verify

Pula verificações de hooks aplicáveis ao commit. Use somente quando souber por que está fazendo isso.

22 · Manutenção e limpeza

Ver objetos soltos

git fsck

Verifica conectividade e objetos no repositório.

Otimizar repositório

git gc

Executa manutenção/limpeza de objetos. Normalmente o Git já realiza manutenção automática.

Ver tamanho

git count-objects -vH

Mostra informações sobre objetos e armazenamento.

Remover referências remotas obsoletas

git fetch --prune

Limpa referências locais de branches que não existem mais no remoto.

23 · Aliases: criar seus próprios atalhos

Status curto

git config --global alias.st "status -sb"

Depois: git st.

Log visual

git config --global alias.lg "log --oneline --graph --decorate --all"

Depois: git lg.

Listar aliases

git config --global --get-regexp "^alias\."

Mostra aliases globais configurados.

24 · Comandos avançados que vale conhecer

Descobrir raiz do repositório

git rev-parse --show-toplevel

Mostra o caminho da raiz do repo.

Mostrar branch atual

git branch --show-current

Retorna apenas o nome da branch atual.

Identificador do commit atual

git rev-parse HEAD

Retorna o SHA do commit apontado por HEAD.

Atualizar branch remota sem merge

git fetch origin main

Busca a referência de main do remoto.

Cherry-pick

git cherry-pick a1b2c3d

Aplica em sua branch a mudança de um commit específico. Pode gerar conflitos.

Abortar cherry-pick

git cherry-pick --abort

Interrompe uma operação de cherry-pick em andamento.

Encontrar branch que contém commit

git branch --contains a1b2c3d

Lista branches locais que contêm aquele commit.

Encontrar tag/branch com commit

git tag --contains a1b2c3d

Mostra tags que contêm o commit.

Ver objetos e referências

git show-ref

Lista referências e seus objetos.

Pacote de uma referência

git archive --format=zip --output=projeto.zip HEAD

Cria um arquivo compactado do conteúdo versionado.

Assinar commit

git commit -S -m "Commit assinado"

Usa assinatura configurada, como GPG/SSH, para autenticar a autoria criptográfica.

Ver configuração de merge/rebase

git config --get-regexp "^(pull|branch|remote)\."

Ajuda a diagnosticar comportamento de branches e remotos.

25 · Problemas comuns e o que fazer

“fatal: not a git repository”

Você provavelmente está fora de um repositório. Entre na pasta correta ou inicialize com git init se for um projeto novo.

“nothing to commit”

Não há mudanças novas para registrar ou você ainda não preparou o que queria. Confira git status.

Push rejeitado

O remoto pode ter commits que você não possui. Veja o estado, faça git fetch e escolha um fluxo apropriado, como integrar/rebasear antes do push.

“branch has no upstream”

No primeiro envio, use git push -u origin nome-da-branch.

Conflito no pull

Não é necessariamente um erro. Resolva os arquivos indicados, faça git add e finalize a operação.

Commit errado já enviado

Para histórico compartilhado, considere git revert. Evite reescrever a branch sem entender o impacto.

Arquivo não aparece no status

Pode estar ignorado. Use git status --ignored e git check-ignore -v arquivo.

GitHub pede autenticação

Confira se a URL é HTTPS ou SSH e configure o método de autenticação correspondente. Não cole tokens ou chaves privadas no código.
